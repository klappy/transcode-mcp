# Bounded read-only documentation through MCP

Status: cookbook implementation proposal, documentation only. User requests today's learnings, validation, choices and rationale accessible through the existing transcode MCP. Current `createServer` registers `generate_transcode_url`; no docs tool exists. Add one small read-only tool in that existing server, without a new service or media execution path.

## Contract

`get_docs({topic?: string})` defaults to `index`. Topic is an exact allowlisted stable ID, never a filesystem path, URL, glob or search expression. Start with `index`, `session-2026-10-05`, `single-baseline`, `video-policy`, `video-sources`, `capacity`, `cache-ownership`, `storage-deadline`, `frame-rate-evidence`, `audio-reuse-evidence` and `modern-codec-history`. The index maps each ID to its title, short scope/status, exact source path and immutable content SHA256. Distinguish current decisions, historical/superseded experiments, and pending validation. Do not describe a proposed tool as deployed until verified through its actual MCP endpoint.

Serve one bundled UTF-8 Markdown document per request, maximum64KiB; index maximum32KiB and at most32 entries. A build step reads only a checked-in curated manifest under the repository, validates relative allowlisted canon paths, rejects symlink/path escape, duplicate IDs, invalid UTF-8 and oversized files, and emits a static module. Runtime reads only that module: no filesystem access, remote source fetch, credentials, container wake, encode, storage mutation or paid API. Reject unknown IDs with a bounded error and index hint; do not guess paths or fetch missing documents. Fail the build instead of silently truncating.

Return a text content block containing the document plus compact provenance: topic, title, status, sourcePath, sourceRevision (exact build source commit), contentSha256 and bytes. Index provenance uses the same fields with an index hash. Hash document bytes exactly, excluding the response wrapper. The deployed build revision is separate from whether a statement inside the document describes an earlier evidence revision. Local unpublished builds must not invent an immutable remote source URL. Retain relative links in canonical Markdown and provide the immutable source revision/path so a caller can resolve them; related exposed topics are discoverable in the index.

Expose the tool as read-only and idempotent, with bounded input (topic≤80 characters; object rejects unknown fields). Do not add arbitrary prompt execution, repository browsing, external link traversal, full-text search or media actions. Existing URL-generation tool behavior and authentication/deployment conventions stay unchanged.

## Implementation and acceptance

Proposed owned files: existing `src/worker.ts` tool registration, a small docs manifest/builder/static JSON catalog (the project already supports JSON imports), focused tests, existing `smoke-mcp.ts`, and the existing build script hook only if needed. Canonical docs remain authored source; the generated catalog must fail drift checks rather than silently serve stale content. No container/encoder/app changes.

Tests must prove actual curated body/hash/length/revision correspondence, exact topic lookup, default index, unknown/path-like/oversized/extra-field rejection, build refusal for invalid/oversize/path-escape input, and no calls to fetch/container/R2 during retrieval. Retain the original URL-generation tests. Through the actual DEV MCP endpoint, `tools/list` must advertise `get_docs`, and `tools/call` must return the session synthesis and single-baseline decision matching the deployed static catalog; verify their exact returned body hashes and statuses. Extend existing MCP smoke checks for tool discovery, default index, exact topic body/hash and unknown-topic errors. Then follow the existing Cloudflare main→DEV smoke→staging→production release gates; no new GitHub Actions deployment path or preview alias. No claim that docs are accessible through MCP before this implementation and endpoint proof.

Rollback removes the tool/catalog registration without changing media delivery. Updates are ordinary reviewed docs/build releases, not autonomous background edits or scheduled benchmarks.
