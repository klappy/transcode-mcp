## Current choices and why

- **One H.264 baseline.** Modern-codec exploration is closed/deferred. HEVC cannot be the sole codec across the stated rolling three-year browser/hardware target; Safari AV1 is hardware-dependent. Extra codec variants, selection logic, storage and CPU are not justified now. Reopen only for a concrete use case whose benefit outweighs those costs. [Decision and primary compatibility sources](2026-10-05-video-single-baseline.md); [superseded exploration](2026-10-05-modern-codec-comparison.md).
- **720 encoded canvas for the current480-viewing use case.** The selected a13 medium recipe preserves50fps and uses two-pass H.264, requested439024bps in the nominal450kbps class, VBV900k/1800k, maximum30second GOP and AAC96k stereo. Sampled480-viewing detail was acceptable for this illustrative resource; foliage loss is visible at full720. It is not high-quality720 or universally suitable for fine text. [Selection](2026-10-04-a13-medium-video-selection.md).
- **480 and720 only in the planned ladder.**540 was removed because its small distinction did not justify complexity. Further frame-rate tradeoffs belong at480 or below only when a concrete benefit warrants them; no lower rung is silently authorized. The present720 baseline remains50fps. [Rendition scope](2026-10-05-dev-video-capacity-cancellation-and-rendition-scope.md).
- **Source identity is separate from logical asset and output identity.** Three verified published HQ sources—a13 Jordan River, a184 Sandals, a10 Wilderness—replace neither the identity nor provenance of old bundled low-resolution files. Source assetVersion1.0.4 is distinct from collectionVersion1.1.2. Exact source/contract/runtime encoder identity determines cache identity. Changing the adapter can change encoder revision even with unchanged encode settings. [Three-source extension](2026-10-05-fia-video-source-extension.md), [original adapter scope](2026-10-04-fia-video-adapter.md).
- **Finish accepted work after viewer disconnect.** Playback Stop, navigation and network loss detach a consumer; they are not an underlying-job cancellation command. The existing Durable Object owns bounded encode, verification, quarantine, publication and cleanup, with same-source/contract singleflight and independent consumer streams. No new service or container credentials for R2. [Ownership](2026-10-05-video-disconnect-cache-ownership.md).
- **Deadlines are truthful about R2.**600seconds bounds execution/consumer waiting and prevents new phases; issued storage operations can settle later. Keep the owner occupied until settlement/cleanup. A predeadline canonical PUT of fully verified bytes may validly complete later. Fifteen-minute DO pending-I/O protection is not a storage rollback guarantee. [Clarification](2026-10-05-video-owner-storage-deadline.md).
- **Latency-first capacity, measured against cost.** Development changed from0.0625vCPU/256MiB to standard-4,4vCPU/12GiB/20GB. CPU billing is active usage; provisioned memory/disk and the existing10minute idle tail matter too. More CPUs can reduce waiting without proportional CPU-work cost, but linear speedup is not assumed. No new encoder thread cap was needed. [Official pricing, arithmetic and rollout gates](2026-10-05-dev-video-capacity-cancellation-and-rendition-scope.md).

## Reusable engineering lessons

1. Compare actual decoded frames using frame-callback/canvas capture at matched timestamps and contain framing. Browser compositor screenshots can retain stale frames. Verify scene correspondence when comparing independently bundled versions; duration similarity is insufficient.
2. Count video, audio and mux bytes separately. Fix audio payload/timing when isolating video; request bitrate is not measured bitrate. A paired-rate gate prevents apparent quality gains caused by extra actual bytes.
3. Preserve pass statistics identities and actual installed executable/library/adapter revisions. Nominal preset names across encoders do not imply equal speed or quality. Bound source/output/statistics/disk/time before executing, and retain failures.
4. A finalized faststart MP4 is still delivered after complete encode and verification in this service. First network byte is not first decoded frame. No progressive-encoding claim follows from moving the moov atom. After the first analysis pass completes, a future streaming-compatible second pass could in principle emit playable output before that pass finishes; the first pass itself is not the deliverable. That requires a separately reviewed streaming-container/client/integrity contract and is deferred, with no implementation or new experiment authorized here.
5. Cache keys need canonical source+settings+actual encoder identity; existing storage avoids repeat work after completion, singleflight avoids duplicates while work is pending. Random routing alone does not supply sharing.
6. Installed-PWA/native-fullscreen behavior and actual mobile codec support require device evidence. Desktop browser and simulated events cannot establish those claims. FIA client lifecycle work and source-bound media descriptors remain separate from server qualification.
